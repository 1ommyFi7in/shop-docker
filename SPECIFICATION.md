# Техническое задание · Запуск магазина в Docker

[← К README](README.md)

## Рабочий сценарий
Коллега получает образ каталога и Compose-конфигурацию. Он запускает PostgreSQL, читает карточку, делает покупку и обновляет контейнеры, сохранив данные. На чистом стенде он может вернуться к стартовой фикстуре.

## Контракт окружения и проверка

- В чистой копии нужны Docker с Compose и доступ к выбранным базовым образам. Сборка Java либо выполняется в Dockerfile, либо документируется как отдельный предварительный шаг. Конфигурация подключения к БД читается из переменных окружения.
- `db` поднимает схему и тестовые данные один раз для чистого тома. Каталог получает имя сервиса `db` как адрес. Readiness проверяется запросом, который показывает наличие требуемой схемы, а не только запущенный процесс.
- На [чистых данных](https://github.com/1ommyFi7in/java-backend-roadmap/blob/main/%D0%9F%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/%D0%9A%D0%BE%D0%BD%D1%82%D1%80%D0%B0%D0%BA%D1%82%D1%8B%20%D0%B8%20%D1%82%D0%B5%D1%81%D1%82%D0%BE%D0%B2%D1%8B%D0%B5%20%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5%20%D0%BC%D0%B0%D0%B3%D0%B0%D0%B7%D0%B8%D0%BD%D0%B0.md#%D0%B1%D0%B0%D0%B7%D0%BE%D0%B2%D1%8B%D0%B5-%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5) запусти `docker compose run --rm catalog show 11 --via jdbc`, затем `docker compose run --rm catalog reserve 7 11 2`. Пересоздай контейнер `db` с тем же томом. Повторное чтение покажет `stock=1`.
- На отдельном чистом томе повторный первоначальный запуск показывает `stock=3`. В README идентифицируй том и уточни, какой шаг сохраняет данные, а какой сбрасывает учебный стенд.

Приложи Dockerfile, Compose-файл, шаблон окружения с фиктивными значениями и вывод обоих прогонов.

## Функциональные требования

- [ ] Собрать образ Java-модуля с явной версией базового образа и entrypoint команды каталога.
- [ ] Описать сервисы `db` и `catalog` в Compose. Настроить сеть, именованный том PostgreSQL, начальную схему и тестовые данные.
- [ ] Перед обращением к БД дождаться готовности инициализированной схемы. Документировать запуск, остановку, просмотр логов и повторное поднятие стенда.
- [ ] По желанию выполнить [лабораторную по Kubernetes](https://github.com/1ommyFi7in/java-backend-roadmap/blob/main/%D0%A2%D0%B5%D0%BE%D1%80%D0%B8%D1%8F/Kubernetes.md) с учебным HTTP-образом и двумя репликами. Посмотреть, как Service обслуживает трафик после удаления одной из реплик.

## Пример ввода и вывода

```sh
docker compose up -d --wait db
docker compose run --rm catalog show 11 --via jdbc
```

```text
11 SKU-11 Кружка 49.90 stock=3
```

Если через CLI разместить заказ на две единицы, перезапустить стенд без удаления тома и повторить команду, ответ заканчивается на `stock=1`.

## Нефункциональные требования

- [ ] Для запуска не требуется установленная на хосте PostgreSQL. БД слушает внутреннюю сеть Compose. Конфигурация и учебные учётные данные задаются окружением.
- [ ] После обычного `docker compose down` и нового запуска данные сохраняются. Инструкция отдельно описывает очистку локального тома для полного сброса.
